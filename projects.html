VR Survival Zombies

2-player co-op VR shooter for Meta Quest · Personal project, 2025–2026 · In review on the Meta Quest Store and SideQuest

My contribution

Sole developer: architecture, netcode, VR interactions, zombie AI, VFX, tests and Quest profiling.

  • Networked weapon pickup, two-handed handling and reloading on AutoHand physics hands, with state authority transferred between players in Photon Fusion 2 Shared Mode.
  • Throwable grenades with physics synchronized across clients.
  • Wave-based zombie AI on NavMesh, simulated by the session master and replicated to the second player.
  • Networked full-body IK avatars: head and hand targets are replicated and each client solves the IK locally, instead of sending bone data.
  • Unit tests with the Unity Test Framework for the scalability-sensitive systems; playtest sessions to find and fix gameplay and network bugs.
  • Custom VFX built within the Quest frame budget; profiled on device to hold the target framerate.

Stack

  • Unity 6
  • C#
  • Photon Fusion 2 (Shared Mode)
  • AutoHand
  • Meta Quest
  • OpenXR
  • NavMesh
  • Unity Test Framework
  • Git

Main technical challenge

Keeping physics-driven interactions consistent for both players. A grenade thrown by one player has to land in the same place for the other, and a rifle grabbed from a teammate has to change authority without snapping. I documented each networked system in the README: when to use replicated state vs. RPCs, how authority transfer works in Shared Mode, why there is no lag compensation in that mode, and the interpolation asymmetry between the owning client and the proxy, measured under simulated latency.

RUN — VR Horror Game

Unity 6 + XR Interaction Toolkit 3 · Team of 2 · Published on itch.io

My contribution

Gameplay programming and the 2025 engine migration. Made with Guillermo Vega, who recorded the gameplay footage.

  • Gesture-driven mechanics: integrated the $P point-cloud recognizer to classify in-air hand strokes as input (gesture locomotion, flashlight recharge), with confidence thresholds and runtime template training.
  • Physics-based climbing driven by hand velocity, built on XRI 3's interactor handedness model, that cleanly takes over from locomotion.
  • Migrated the project from deprecated XRController APIs to Unity 6, XRI 3.3 and OpenXR.
  • NavMesh enemy AI and a resource-driven flashlight loop.

Stack

  • Unity 6
  • C#
  • XR Interaction Toolkit 3
  • OpenXR
  • $P recognizer
  • NavMesh

Main technical challenge

Turning noisy controller trajectories into reliable gameplay input. A stroke has to be recognized as "run" quickly enough to feel responsive, but not so loosely that reaching for the flashlight triggers it. The answer was a template-based classifier with a tuned confidence threshold and the ability to record new templates at runtime.

VR Anesthesiology Simulation

Virtual Medical Learning · Unity VR Developer · June 2024 – June 2025 · Meta Quest 3

My contribution

Took features from concept through implementation, on-device testing and release, working directly with medical advisors to translate clinical requirements into VR interactions.

  • Spatial interaction systems: constrained free-hand ultrasound probe movement to anatomical splines via vector projection, driving position-indexed ultrasound imagery that stayed in sync with the probe.
  • Instrument handling, controlled strokes and haptic feedback built on Unity's New Input System; Observer pattern, interfaces and event-driven architecture to decouple systems.
  • Integrated and configured AutoHand 4, Quest Machine, Dialogue System and Odin Inspector to speed up the pipeline.
  • Profiled and optimized on Quest 3 to hold the target framerate.
  • Presented the simulation to medical audiences and turned their feedback into iterations.

Stack

  • Unity
  • C#
  • Meta Quest 3
  • New Input System
  • AutoHand 4
  • Quest Machine
  • Dialogue System
  • Odin Inspector
  • Haptics
  • Unity Profiler

Main technical challenge

The ultrasound transducer. Physicians move the probe freely, but the image shown has to correspond to a real anatomical position. I projected the hand position onto a spline that follows the anatomy, used the resulting parameter to index the imagery, and kept the probe visually attached to the body without fighting the user's hand.
